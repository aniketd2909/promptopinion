Suno Clinical Scribe

Turning doctor–patient conversations into structured FHIR — automatically.

The Problem — Documentation Burden & Diagnostic Load

5.8 / 8 hrs Ambulatory physicians spend ~5.8 hours on the EHR for every 8 hours of scheduled patient time.1
62% of burnt-out physicians cite bureaucratic workload & EHR demands as the top driver of burnout.2
How charts get filled in today
  • Manual entry — clicking checkboxes, dropdowns, free-text narratives during & after the visit
  • Human scribes — a second person in the room doing data entry so the doctor can focus
  • Dictation (Nuance Dragon, etc.) — speech-to-text of a post-visit summary
  • Ambient AI scribes — listens to the conversation, drafts a structured note for the doctor to review & sign
Ambient AI scribes only solve documentation. Suno goes further: as the doctor talks, it pulls the patient's prior history, meds & allergies from the EHR and surfaces a live differential diagnosis with next steps — then writes the approved encounter back as structured FHIR any EHR can ingest.

1 AMA, Five physician specialties that spend the most time in the EHR (2024), based on Epic data from 200,000+ physicians. 2 Medscape Physician Burnout & Depression Report (2024–25); see also Tebra 2025 Physician Burnout Survey.

① Doctor's Chat Agent

Conversational UI where the doctor pastes a transcript or uploads audio. Thin, focused, human-in-the-loop. Works against any MCP-compliant clinical backend — not locked in.

② MCP Server

19 governed tools — 9 FHIR read, 7 FHIR write, 3 AI agents (transcribe → structure → diagnose). Pluggable into Prompt Opinion, Claude Desktop, or any MCP client.

SHARP-on-MCP: the platform injects FHIR server URL + access token per request, so the same code runs against any FHIR R4 EHR.

Architecture

Doctor → LLM → MCP Server → Gemini + FHIR EHR. One server, three AI agents, sixteen governed tools.

🎙️ Input — Audio

Doctor–Patient consultation audio recordings from a public Kaggle dataset. — simulated clinical conversations, complete with small talk, interruptions, and accents, fed straight into the transcriber agent.

🏥 Back end — FHIR

Live reads & writes against the public HAPI FHIR R4 test server — hapi.fhir.org/baseR4. Every GetPatient, SuggestDiagnosis, and CommitEncounter call is a real HTTP round-trip to a hosted R4-compliant EHR.
